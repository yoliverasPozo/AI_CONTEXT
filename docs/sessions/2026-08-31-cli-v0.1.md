# Session: Build CLI v0.1 initializer

Date: 2026-08-31

## Goal

Implement the first optional AI_CONTEXT tooling milestone: a small `ai-context init` command that scaffolds the repository-native shared-memory structure without making the CLI a requirement of the convention.

The work was intentionally performed through the full GitHub feature-branch, commit, pull-request, review, and merge workflow so the repository continues to dogfood its own version-controlled-memory model.

## Investigation

Before implementation, the repository's live `AGENTS.md`, `docs/AI_CONTEXT.md`, latest session handoff, canonical `templates/AI_CONTEXT.md`, and agent examples were reviewed.

The main design questions were:

- whether the initial CLI should use Python, Node, Go, or shell;
- whether initialization should depend on an LLM;
- how to preserve vendor neutrality while offering agent-specific adapters;
- how to avoid silently overwriting existing repository instructions or live context;
- how an installed package can carry the canonical Markdown resources without drifting from the reference files.

Python 3.10+ with a standard-library-only runtime was selected and recorded in ADR 0002.

## Decisions

- Implement distribution `ai-context`, import package `ai_context`, version `0.1.0`.
- Keep runtime dependencies empty and make no LLM or network calls.
- The CLI scaffolds memory; humans and AI agents populate and maintain it.
- `ai-context init` always creates the core AI_CONTEXT memory layer and optionally installs agent adapters.
- Agent adapters are opt-in so the core initializer does not privilege one provider.
- Supported v0.1 adapter names are `codex`, `claude`, `gemini`, and `generic`.
- Existing managed files cause initialization to abort unless `--force` is explicit.
- Add `--dry-run` so users can inspect planned writes.
- Bundle the required Markdown resources with the Python package and test them byte-for-byte against the canonical repository templates/examples.
- Add cross-platform GitHub Actions now that the repository has executable code and meaningful tests.

## Tests and Validation

Local validation before the feature was pushed into the PR workflow:

- `python -m unittest discover -s tests -v` — 11 tests passed.
- Installed the package in editable mode with no runtime dependencies.
- `ai-context --version` returned `ai-context 0.1.0`.
- In a temporary Git repository, `ai-context init --agents codex,gemini` created:
  - `docs/AI_CONTEXT.md`
  - `docs/decisions/`
  - `docs/sessions/`
  - `AGENTS.md`
  - `GEMINI.md`
- A repeated `ai-context init --agents codex` returned exit code 1 and refused to overwrite the existing managed files.

The feature also adds GitHub Actions so the pull request can validate Linux/Windows behavior on Python 3.10 and 3.13.

## Problems Encountered

A v0.1 usability limitation became clear while designing safe overwrite behavior: because `init` treats all existing managed files as conflicts, it is not yet convenient to add one adapter to a repository that already has a populated `docs/AI_CONTEXT.md`. Using `--force` would also replace the existing live context, which may be undesirable.

This limitation is intentionally documented rather than hidden. A future iteration should support surgical/idempotent operations that preserve existing live memory while adding or refreshing selected adapters.

No failure was found in the tested v0.1 behavior itself.

## Current Result

The `feat/cli-v0.1` branch contains the first executable AI_CONTEXT tooling release candidate, its architectural decision record, automated tests/CI, public usage documentation, and updated live project memory.

The core convention remains fully usable without installing the CLI.
